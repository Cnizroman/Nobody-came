# «Никто не вспомнит» — интерактивный литературный проект

**«Никто не вспомнит»** — авторский литературный сайт Cnizroman: тетралогия, отдельные произведения и архив материалов о создании историй. Это не просто сборник текстов, а интерактивное пространство с атмосферным оформлением, навигацией по книгам и системой читательских рецензий.

- **Сайт:** https://cnizroman.github.io/Nobody-came/
- **Стек:** HTML, CSS, JavaScript, Supabase
- **Публикация:** GitHub Pages

## 📚 Произведения

### Тетралогия

1. **Дорога из Холода**
2. **Спасательный круг**
3. **Где нас нет**
4. **7 Дней**

- **Белая голова** — самостоятельный психологический детектив, не входящий в тетралогию.

На главной странице можно перейти к прологу, книгам и отдельной истории. В архиве автора собраны отсылки, мысли о проекте, визуальные материалы, вырезанные фрагменты и черновики.

## ⭐ Система рецензий

Для каждого произведения оценки считаются отдельно. Читатель оценивает пять критериев:

| Критерий | Максимум |
| --- | ---: |
| Сюжет | 5 |
| Персонажи | 4 |
| Атмосфера | 4 |
| Язык и стиль | 4 |
| Эмоциональное воздействие | 4 |
| **Всего** | **21** |

Новые рецензии поступают на проверку. На сайте отображаются только опубликованные записи.

### Панель модерации

После настройки Supabase панель доступна по адресу:

**https://cnizroman.github.io/Nobody-came/reviews-admin.html**

Для входа нужна учётная запись Supabase, а её email должен быть добавлен в таблицу `review_admins`. Ссылка на панель не заменяет авторизацию: доступ к данным должен контролироваться настройками Supabase и Row Level Security.

Инструкция по настройке находится в [`SUPABASE_SETUP.md`](SUPABASE_SETUP.md).

## 🚀 Запуск и публикация

### Открыть сайт локально

Можно открыть `index.html` в браузере. Для более корректной проверки JavaScript, манифеста и service worker запусти локальный HTTP-сервер из папки проекта:

```bash
python -m http.server 8000
```

Затем открой `http://localhost:8000`.

### Опубликовать через GitHub Pages

1. Загрузи **содержимое папки проекта** в корень репозитория — файл `index.html` должен находиться в корне.
2. Открой настройки репозитория: **Settings → Pages**.
3. В разделе сборки выбери публикацию из ветки (обычно `main`) и папку `/ (root)`.
4. Сохрани настройки и дождись публикации.

Если сайт уже опубликован, после изменения файлов достаточно отправить коммит в настроенную ветку. Если менялись `style.css`, `visuals.js` или другие кешируемые файлы, проверь номер кеша в `sw.js` и при необходимости увеличь его, чтобы браузеры получили обновления.

## 🗄️ Настройка Supabase

Система рецензий требует отдельного проекта Supabase. Основные файлы:

- `supabase-config.js` — URL проекта и публичный publishable key.
- `supabase-schema.sql` — SQL для создания таблиц и политик.
- `supabase-hardening.sql` — дополнительные настройки защиты.
- `SUPABASE_SETUP.md` — пошаговая инструкция.
- `review-system.js` — логика рецензий.
- `reviews-admin.html` — панель модерации.

**Важно:** в клиентском `supabase-config.js` допустим только публичный publishable/anon key. Не добавляй туда `secret` или `service_role` key. Публичный ключ сам по себе не заменяет защиту: права доступа должны быть правильно настроены политиками RLS в Supabase.

## 🔐 Защищённая третья книга

Текст книги 3 хранится в зашифрованном виде и расшифровывается в браузере после ввода пароля. Чтобы изменить пароль, недостаточно поменять строку в HTML: содержимое необходимо заново зашифровать и обновить данные в `book3.html`.

## ♿ Доступность и производительность

Визуальные эффекты учитывают настройку `prefers-reduced-motion`; на сенсорных устройствах часть эффектов наведения отключена. Service worker кеширует посещённые страницы, чтобы ранее открытые материалы могли быть доступны без подключения к сети.
